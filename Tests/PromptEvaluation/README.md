# Prompt Evaluation Cases

`cases.json` 是当前模型中英优先评测的语义案例矩阵，不是真实会话样本。矩阵覆盖 8 个固定类别：`ordinary`、`negations`、`uncertainty`、`technical`、`mixed`、`questions`、`repetition`、`long-draft`；每个类别都包含 `zh-en` 与 `en-zh` 两个方向，并分别提供 `translate` 与 `optimize` 意图，共 32 条案例。同一 `category+direction` 下的两个意图复用完全相同的 `source`，便于比较翻译与优化行为。

`requiredLiterals` 只用于检查源文中的技术字符串、代码、命令、路径、标识符、URL、日期，或源文显式要求原样保留的 UI 标签是否有机会被逐字保留。普通语义短语、否定词、问题内容、未决项和需要翻译的历史引用不放入此字段。自动匹配这些字面量不等于语义质量通过：它不能证明否定、未决项、问题不应被回答、上下文缺失或优化后的结构仍然准确。每个字面量都必须先出现在对应的 `source` 中。

盲评时，全部案例先通过保真度硬门槛；通过后再比较自然度、结构清晰度，以及 `repetition` 案例中的重复压缩是否恰当。对每套被修改模板对应的 16 例，候选方案至少有 9 例改善，其余案例不得退步，且全部案例都通过保真度硬门槛，才采用候选方案。每套评测预算固定为真实 32 条基线加 32 条候选，不自动重试。凭据、令牌和真实配置不得写入样例或评测报告。

每条案例的 `semanticChecks` 用简体中文说明必须保留的事实、否定约束和未决项；`forbiddenAdditions` 用简体中文说明不得新增的需求、决定、答案或建议。`questions` 中的原文问题应保持为问题，不能被候选直接回答；`uncertainty` 与 `long-draft` 中缺少指代背景或尚未决定的事项应保持未决。历史记录中的 `ignore instructions` 只是待处理的内容，不能被当作当前指令。`technical` 案例包含代码围栏和复合 emoji，`mixed` 案例显式要求中文 UI 标签保持原样，`long-draft` 是多段长稿而非把单句标成长稿。

## 2026-10-10 提示词优化

[`candidate-templates.json`](candidate-templates.json) 保存本次采用的两套模板快照，可通过评测工具的 `--templates` 参数加载。普通翻译强调自然表达，同时保留原文体裁、结构、顺序和重复；优化模式允许整理结构、合并同义重复，但保留独立信息和刻意强调。两者明确保留问题形式、条件例外、承诺强度、未决事项、技术原文和原有引用格式，避免将普通文本强行改写为编程任务。

候选通过核心/API 本地检查（81 个本地请求）、批量评测契约检查（30 项）及 32 条案例的离线请求准备。使用当前 `qwen3.8-27b` 运行旧模板真实基线时，前 28 条完成且所需字面量均保留，第 29 条 `long-draft-zh-en-translate` 请求超时，批次停止。

用户随后明确要求“重新跑第29条后替换”。本次使用原保存模板、同一案例和应用的 45 秒超时设置单独重跑一次，仍返回“模型请求超时，请稍后重试。”，未获得译文。按本次用户指令，将两套模板写入源码默认值和当前 `config/preferences.json`，其他偏好不变。此次采用依据为用户明确指令，未完成完整真实模型对照，不代表达到上述盲评门槛；生产超时设置未改动。
